# 도시 전투 단일 지점 스폰 로직 설계 (City Combat Single Point Spawn Design)

## 1. 개요 (Overview)

본 문서는 도시 전투(`CityCombatState`) 시스템에서 파생되는 플레이어 방어전(`PlayerDefenseState`) 및 라이벌 도시 공격전(`RivalAssaultState`) 모드에서, 공격자가 맵을 360도 둘러싸며 등장하는 기존 방식을 변경하여 **맵 외곽의 무작위 단일 지점(클러스터)에서 집중적으로 진입**하도록 스폰 로직을 개선하기 위한 설계 문서입니다.

이러한 변경을 통해 플레이어는 매 전투마다 특정 방향에서 몰려오는 적에 대항하는 예측 불가능한 전술적 상황을 경험하게 되며, 수비벽 구축이나 방어 타워 배치에 있어 보다 다채로운 전략을 요구받게 됩니다.

---

## 2. 핵심 요구사항 (Key Requirements)

- **단일 지점 지향성 보장**: 웨이브마다 스폰되는 적(또는 아군)이 설정된 단일 방향을 기준으로 군집을 이루어(Cluster) 진입해야 합니다.
- **전투 세션별 무작위 방향 결정**: 맵의 어느 쪽에서 적이 진입할지 알 수 없도록, 각 전투 세션이 초기화될 때(`initMode`) 무작위로 한 방향을 결정해야 합니다. 전투가 지속되는 동안(웨이브 반복 시) 이 진입 방향은 유지됩니다.
- **RivalAssault(공격) 스폰 변경**: 플레이어가 라이벌 도시를 공격할 때, 고정된 `new THREE.Vector3(1, 0, 1)` 방향이 아닌 전투 시마다 랜덤한 방향의 외곽에서 진입하도록 개선합니다. (라이벌 도시 방어군은 기존처럼 코어 반경에 스폰 유지)
- **PlayerDefense(방어) 스폰 변경**: 몬스터 웨이브 스폰 시 `center`를 기지 밖 단일 지점으로 밀어내어, 360도 스폰을 한쪽 방향 스폰으로 변경합니다.
- **게임 밸런스 유지**: 적이 뭉쳐서 나오는 만큼 광역 공격 등에 취약해질 수 있으나, 본 문서의 범위는 스폰 위치 로직 개선에 한정하며 유닛 스펙 등의 밸런싱은 추후 별도로 진행합니다.

---

## 3. 세부 구현 가이드 (Implementation Details)

### 3.1 PlayerDefenseState (방어전 몬스터 스폰 변경)

기존 방어전은 `this.spawnPos`(주로 맵 중앙 또는 `ArmyFlag` 위치)를 중심으로 큰 반경 원호 상에 몬스터를 360도로 흩뿌렸습니다. 이를 개선하기 위해 **전투 진입 시 적이 몰려올 무작위 방향 벡터(`enemySpawnDir`)**를 설정하고, 웨이브 스폰 중심(`center`)을 해당 방향으로 밀어냅니다.

`resolveWaveSpawnParams`를 오버라이드하여 `center`를 `enemySpawnDir` 방향으로 40~50미터 밀어내고, `radius`를 8~10미터 정도로 좁혀 군집을 형성합니다.

### 3.2 RivalAssaultState (공격전 플레이어 진입 변경)

기존 라이벌 공격전에서 플레이어 진입 위치는 코어를 중심으로 `new THREE.Vector3(1, 0, 1)` 방향 최외곽으로 하드코딩 되어 있었습니다. 이를 `initMode`에서 결정된 무작위 `entryDir`을 사용하도록 `resolveRivalCityEntrySpawnPos` 메서드를 수정합니다.

## 4. 예외 및 고려사항 (Edge Cases)

- **지형/장애물 충돌(Collision)**: 단일 지점 스폰 시 몬스터 간 겹침 현상이 심해질 수 있습니다. 기존 `BaseCityCombat.spawnCombatWave()`에 구현된 스폰 알고리즘(원형 분산)이 클러스터 반경 내에서 충분히 동작하므로 큰 문제는 없으나, 심각한 밀집 시 충돌 박스 밀어내기(Push-out) 또는 물리 보정(physics check)이 강화되어야 할 수 있습니다.
- **`ArmyFlag` 적용(PlayerDefense)**: 방어전에서 `ArmyFlag`가 존재할 경우, `this.spawnPos`가 해당 깃발의 위치로 변경됩니다. 이 경우 `clusterCenter`는 깃발을 기준으로 `enemySpawnDir`로 더 바깥쪽에 형성되므로 전술적 의도에 부합합니다.

## 5. 검증 계획 (Validation Plan)

1. **빌드 검증**: `npm run build`를 통해 타입 오류 및 오버라이딩 정상 적용 여부를 확인합니다.
2. **방어전 (PlayerDefenseState) 테스트**:
   - 몬스터가 360도로 흩어지지 않고, 한쪽 방향에 밀집된 상태로 걸어오는지 확인합니다.
   - 전투를 포기/종료 후 다시 방어전에 돌입하면, 이전과 다른 랜덤한 방향에서 몬스터가 등장하는지 확인합니다.
3. **공격전 (RivalAssaultState) 테스트**:
   - 적 도시에 진입할 때마다 플레이어 스폰 시작 지점이 다양한 방향에서 맵 안쪽을 바라보는 형태로 떨어지는지 확인합니다.
   - 방어군(적군)은 진입 방향에 관계없이 여전히 적 도시 중심(Core) 주변에 스폰되어 기다리고 있는지 확인합니다.
